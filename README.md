## HR 手册协作约定：功能更新通知

2026 年 11 月 13 日确认：后续 TalentGo 功能更新通知，统一沿用用户提供的《TalentGo OFFER录用流程更新通知》的结构与写法。本节作为本项目的通知写作约定。

### 内容与写法

- 面向 HR、招聘负责人和 HRBP，用实际工作任务组织内容。说明到哪里操作、核对什么、点击什么以及完成后继续做什么。
- 标题使用 `# TalentGo {本次主题}更新通知`，随后用一个简短段落说明本次更新内容及对招聘工作的帮助。
- 使用 `## ✨ 本次更新内容`，按工作顺序拆成 `### 1. ...`、`### 2. ...` 等小节；小节标题使用具体动作，数量按本次更新范围确定。
- 每个小节以简短列表说明变化和操作。页面路径、按钮、关键字段及重要单位用 **加粗** 强调；入口和按钮名称采用 `**「页面 → 区域 → 按钮」**` 的写法，名称以当次已确认页面为准。
- 小节末尾可用 `>` 引用块说明与该操作直接相关的条件、边界或后续动作，避免重复正文。
- 使用 `## 🔔 使用提醒` 收尾。对会影响实际操作的重要限制单独加粗，再补充必要的核对与跟进要求。
- 结尾保留异常反馈入口提示：`如遇使用异常，请反馈对应页面截图及操作步骤。` 涉及个人信息的截图应先脱敏。
- 通知正文以文字和列表为主，不沿用长篇手册式章节或大表格，不加入分支名、提交记录、实现细节等与 HR 操作无关的信息。
- 格式参考与业务规则分开处理。Offer 有效期、计薪单位、候选人反馈等仅用于对应功能；每条业务规则按本次已确认内容填写，不把示例中的专属规则作为其他通知的默认规则。
- 输出标准 Markdown，不保留聊天复制产生的转义反斜杠。草稿日期、生效时间和发布状态可放在文件开头的 HTML 注释中，正式通知正文保持简洁。
